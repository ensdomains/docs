# Address Lookup [Resolve blockchain addresses from human-readable names with ENS.]

A forward lookup takes an ENS name and returns its address. Use this wherever a user can enter a recipient, including payments and messaging.

<Card className="flex justify-center">
  <EnsProfile name="nick.eth" />
</Card>

Treat all valid dot-separated names as potential ENS names, since ENS supports [many TLDs](/dns/tlds).

## Getting the User's Ethereum Address

Use a library that resolves through the [Universal Resolver](/resolvers/universal). The examples require viem 2.35.0 or later, ethers 6.17.0 or later, ENSjs 4.2.3 or later, web3.py 7.16.0 or later, or alloy-rs 2.4.2 or later. See [ENSv2 library support](/web/ensv2-readiness) for the full list.

Replace `<MAINNET_RPC_URL>` with your Ethereum Mainnet RPC endpoint in each example.

These examples resolve `nick.eth`. Replace it with the normalized user input in your application. A name's records can change, so use the returned address rather than a cached example value.

The Wagmi examples were tested with Wagmi 2.19.5 and viem 2.57.10. Configure `WagmiProvider` with Ethereum Mainnet and wrap your app in `QueryClientProvider`, as described in the [Wagmi setup guide](https://wagmi.sh/react/getting-started).

:::code-group

```tsx [Wagmi]
import { normalize } from 'viem/ens'
import { useEnsAddress } from 'wagmi'

export function Address() {
  const { data, isPending, error } = useEnsAddress({
    name: normalize('nick.eth'),
    chainId: 1,
  })

  if (isPending) return <span>Loading…</span>
  if (error) return <span>Lookup failed</span>
  return <span>{data ?? 'No address set'}</span>
}
```

```ts [Viem]
import { createPublicClient, http } from 'viem'
import { mainnet } from 'viem/chains'
import { normalize } from 'viem/ens'

const client = createPublicClient({
  chain: mainnet,
  transport: http('<MAINNET_RPC_URL>'),
})
const address = await client.getEnsAddress({
  name: normalize('nick.eth'),
})
```

```ts [Ethers]
import { JsonRpcProvider } from 'ethers'

const provider = new JsonRpcProvider('<MAINNET_RPC_URL>')
const address = await provider.resolveName('nick.eth')
```

```ts [ENSjs]
import { addEnsContracts } from '@ensdomains/ensjs'
import { getAddressRecord } from '@ensdomains/ensjs/public'
import { createPublicClient, http } from 'viem'
import { mainnet } from 'viem/chains'
import { normalize } from 'viem/ens'

const client = createPublicClient({
  chain: addEnsContracts(mainnet),
  transport: http('<MAINNET_RPC_URL>'),
})
const record = await getAddressRecord(client, {
  name: normalize('nick.eth'),
  coin: 'ETH',
})
const address = record?.value
```

```python [web3.py]
from web3 import Web3

w3 = Web3(Web3.HTTPProvider('<MAINNET_RPC_URL>'))
address = w3.ens.address('nick.eth')
```

```rust [alloy-rs]
use alloy::{ens::ProviderEnsExt, providers::ProviderBuilder};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let provider = ProviderBuilder::new()
        .connect_http("<MAINNET_RPC_URL>".parse()?);
    let address = provider.resolve_name("nick.eth").await?;
    println!("{address}");
    Ok(())
}
```

:::

A name may have no address record. Handle that result before using it as a transaction recipient. To learn what happens under the hood, read [Resolution](/resolution).

## Multichain Addresses

ENS names can store addresses for Ethereum L2s and other blockchains. Use a [SLIP-0044](https://github.com/satoshilabs/slips/blob/master/slip-0044.md) coin type for non-EVM networks. For EVM chains other than Ethereum Mainnet, derive the coin type from the chain ID using [ENSIP-11](/ensip/11), even if the chain also has a SLIP-0044 entry.

<FrenCallout fren="lili" variant="note" title="Resolve from Ethereum Mainnet">
  The destination chain determines the record to request. The resolution call
  still starts on Ethereum Mainnet, including when the requested address is for
  an L2.
</FrenCallout>

These examples request the Base address for `gregskril.eth`. The viem example also requests the Bitcoin record as bytes.

:::code-group

```tsx [Wagmi]
import { toCoinType } from 'viem'
import { base } from 'viem/chains'
import { normalize } from 'viem/ens'
import { useEnsAddress } from 'wagmi'

export function BaseAddress() {
  const { data, isPending, error } = useEnsAddress({
    name: normalize('gregskril.eth'),
    coinType: toCoinType(base.id),
    chainId: 1,
  })

  if (isPending) return <span>Loading…</span>
  if (error) return <span>Lookup failed</span>
  return <span>{data ?? 'No address set'}</span>
}
```

```ts [Viem]
import { createPublicClient, http, toCoinType } from 'viem'
import { base, mainnet } from 'viem/chains'
import { normalize } from 'viem/ens'

const client = createPublicClient({
  chain: mainnet,
  transport: http('<MAINNET_RPC_URL>'),
})
const name = normalize('gregskril.eth')
const baseAddress = await client.getEnsAddress({
  name,
  coinType: toCoinType(base.id),
})
const bitcoinBytes = await client.getEnsAddress({ name, coinType: 0n })
```

```ts [Ethers]
import { JsonRpcProvider } from 'ethers'

const provider = new JsonRpcProvider('<MAINNET_RPC_URL>')
const resolver = await provider.getResolver('gregskril.eth')
const baseAddress = await resolver?.getAddress(2147492101)
```

```python [web3.py]
from web3 import Web3

w3 = Web3(Web3.HTTPProvider('<MAINNET_RPC_URL>'))
base_address = w3.ens.address('gregskril.eth', coin_type=2147492101)
```

### Decoding Address Records

Resolvers return address records as bytes. Some libraries decode them for you. Viem's `getEnsAddress` returns hex-encoded bytes, so decode non-EVM records into the destination chain's address format before displaying or using them. The [address-encoder](https://github.com/ensdomains/address-encoder) package provides coin-specific decoders.
